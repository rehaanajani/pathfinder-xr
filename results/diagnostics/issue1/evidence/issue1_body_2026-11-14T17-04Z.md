## Outcome

Make the sensor-health, fault-isolation and fusion library correct, causal, numerically stable and covered by regression tests using the configuration actually shipped. A passing unit suite alone must not be described as production readiness.

This is **workstream 1 of 3** in the complete Path Finder roadmap. It owns estimator correctness; workstream 2 owns real visual measurements and scientific evaluation; workstream 3 owns reproducibility, deployment and submission. See the linked roadmap issues below.

## Starting evidence and review discipline

Baseline inspected: `main` at `ff7ec4411d8d295de68dba11425f331153562e9b` (14 Nov 2026). The delegated audit ran 12 tests, a two-sequence synthetic evaluation, targeted synthetic probes and laptop ONNX timing. It did **not** reproduce the full TLIO/TUM-VI benchmarks. Audit probe values identify issues to reproduce, not certified hardware performance.

Preserve the current release, results, configs and failed runs before changing behaviour. Reproduce each finding with a minimal test; attach the configuration, seed, checkpoint and result. Reassess findings if the implementation changes.

## A. Fix camera fault rejection and recovery

- [ ] Reproduce the wrong-camera failure using `pathfinder.pipeline.ours_cfg()`, rather than only `FilterConfig()`. Audit locations: `pipeline.py:28`, `tests/test_filter.py:47`, `filter.py`.
- [ ] Explain why adaptive process-noise inflation and/or the recovery logic allow a healthy-looking wrong position fix to regain influence. A large innovation alone does not establish whether the camera or the inertial estimate is wrong.
- [ ] Define and implement the state transitions for normal tracking, degraded vision, visual outage, suspicious visual jump, consistent recovery, and simultaneous sensor degradation.
- [ ] Prevent rejected visual measurements from silently increasing their own future influence through adaptive process noise. Add caps, hysteresis and independent consistency evidence where needed; document the chosen mechanism.
- [ ] Test persistent wrong fixes, gradual visual drift, isolated jumps, repeated faults, partial recovery and a camera returning with a genuine correction after inertial drift.
- [ ] Express hold-out and recovery durations in timestamps/seconds, not an assumed number of camera updates. Test irregular rates and dropped frames.
- [ ] Demonstrate that protection against wrong fixes does not prevent legitimate recovery. A 10-second wrong-fix test must not be the only case when the hold-out constant is also 10 seconds.
- [ ] Include perfect-displacement-oracle diagnostics to isolate filter behaviour, but label oracle data and keep it outside all scored estimator inputs.

## B. Repair the IMU confidence contract

- [ ] Reproduce `pipeline.py` returning `confidence = w.max(0)`: with three or more IMUs, retaining any sensor generally leaves this at 1.0.
- [ ] Separate **relative sensor agreement**, **fault attribution**, **number/geometry of usable sensors**, and **absolute motion confidence**. Agreement cannot establish that common-mode bias/noise is absent.
- [ ] Define a calibrated confidence/quality contract consumed by the filter. State what is observable and which common-mode failures require additional evidence.
- [ ] Propagate quality correctly to process covariance and the learned-motion fallback, including all-unhealthy, missing, stuck, saturated and non-finite inputs.
- [ ] Avoid an unexplained return to equal averaging when every sensor is rejected. Expose a degraded/lost state and conservative uncertainty.
- [ ] Verify confidence and covariance responses to one faulty sensor, multiple faults, correlated faults, all-sensor noise and common-mode drift. Never consult injected fault labels to compute runtime confidence.
- [ ] Confirm fused samples, per-window health and timestamps align, including incomplete final windows and changes of sample rate.

## C. Make multi-IMU fault isolation physically and statistically defensible

- [ ] Resolve the unused `lever_arm_compensate()` in `parity.py`. The current parity model compares co-located measurements; the README says it models lever arms.
- [ ] Either integrate calibrated sensor-to-body rotations, positions, rigid-body acceleration terms and time alignment, **or** explicitly scope support to aligned/co-located simulated sensors and remove broader claims. Hardware support remains blocked until validated.
- [ ] Test fault-free rotation with nonzero lever arms, fast angular acceleration, mounting-axis differences and timing offsets. Do not subtract real rigid-body motion as though it were a sensor fault.
- [ ] Replace or justify scalar noise normalization estimated from the first ten windows. Account for covariance, bias offsets, correlation, uncertainty in estimated noise and calibration contamination.
- [ ] Define startup/warm-up behaviour: calibration may only use data already received, and faults present during warm-up must not be silently learned as healthy.
- [ ] Measure false alarms and detection/isolation separately across seeds, axes, fault types and severity. Include detection delay, false isolation, missed faults and confidence intervals.
- [ ] Verify chi-square assumptions before assigning a nominal false-alarm probability. For very small rates, use enough independent samples or explicit statistical bounds; a short clean trace cannot verify a 0.01% target.
- [ ] Document the two-sensor ambiguity and the assumptions under which three or more sensors can isolate a fault. Multiple simultaneous faults and common-mode errors need explicit limitations.

## D. Filter, uncertainty and learned-model correctness

- [ ] Audit prediction/update ordering, coordinate frames, gravity direction, quaternion convention, units, bias states, interpolation and initial covariance.
- [ ] Test covariance symmetry and positive semidefiniteness, finite outputs and numerical stability during long runs, repeated rejection/recovery and cloning. Prefer stable solves to unnecessary matrix inverses.
- [ ] Verify error-state injection/reset, stochastic-clone covariance/Jacobians, clone removal and yaw-frame measurement mathematics against analytic or finite-difference checks.
- [ ] Audit the learned-model self-check and adaptive covariance for circular confidence, instability and correlated observations. Overlapping learned windows are not independent measurements.
- [ ] Evaluate uncertainty using defined multivariate covariance coverage / Mahalanobis regions, NIS/NEES where applicable and reliability plots. Do not interpret a scalar norm within three reported standard deviations as automatically equivalent to 99.7% 3D coverage.
- [ ] Define behaviour for insufficient motion, unobservable heading, missing cameras and both modalities being poor. Emit validity, reason codes and growing uncertainty instead of silently asserting accurate tracking.
- [ ] Implement/document a realistic initialization path using available measurements, including gravity/bias warm-up and initial velocity assumptions. Preserve truth-initialized runs only as explicitly labelled diagnostic/benchmark modes.
- [ ] Inspect training/inference frame consistency and the use of preprocessed bias-compensated TLIO data. Distinguish valid inverse frame conversion from genuinely unavailable runtime information.
- [ ] Investigate why adding the network worsens clean tracking and short outages. Establish a validation-tested activation/weighting policy rather than always adding another correlated update.
- [ ] Compare existing settings, cloning/covariance calibration and the wider network on validation only. A lower window RMSE does not establish better end-to-end tracking.

## E. Regression and interface coverage

- [ ] Parameterize tests around the actual public pipeline configuration and supported alternate configurations.
- [ ] Include single-IMU, two-IMU and redundant-IMU paths; zero/one frame, short recordings, empty fault lists, variable timestamps, invalid shapes and missing data.
- [ ] Add deterministic regression fixtures for every confirmed defect and verify failures before fixes.
- [ ] Define the estimator input/output contract: timestamped measurements, calibration, frames, pose, velocity if supported, covariance convention, tracking state and diagnostic counters.
- [ ] Make runtime code independent of reference trajectories, clean counterpart images, injected failure schedules and scoring-only labels. Test the production path with reference fields absent.
- [ ] Keep diagnostics/oracles explicitly separated and retain error cases; no silent repair that makes a failed tracking run look successful.

## Acceptance gate

- [ ] Each confirmed finding has a reproducible regression and an explanation of the final fix or explicit supported-scope restriction.
- [ ] Wrong-fix protection and genuine outage recovery both pass the same frozen production configuration across multiple seeds and durations; attach paired results and validation-defined limits.
- [ ] IMU quality is informative under the supported fault assumptions and uncertainty is conservative when those assumptions fail.
- [ ] Physical multi-IMU support is either validated with geometry-aware tests or clearly marked unsupported pending hardware.
- [ ] False-alarm/coverage claims have sufficient statistical evidence; thresholds and operating envelopes are documented.
- [ ] A reference-free streaming API works; truth-based initialization and oracle experiments are separately labelled.
- [ ] Tests, code comments, README and configuration names describe the same behaviour.
- [ ] Link commits, commands, configs, fixtures and measured evidence in this issue before closure.
